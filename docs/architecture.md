# Architecture

```
 your code
    |  import pypdfcraft
    v
 pypdfcraft (src/pypdfcraft)                                    pure Python
    api.py / features.py / editing.py    one-call functions, optional output paths
    oneshot.py (generated)               one typed function per engine tool
    core.py / tools.py                   Document, tool registry (schemas -> signatures)
    _bindings.py (generated)             UniFFI Python bindings (ctypes)
    _loader.py                           finds / loads the native library per platform
    |  ctypes
    v
 native library  _lib/libpdfcraft_engine.{so,dylib} | pdfcraft_engine.dll       Rust
    rust/apps/pdfcraft-android           UniFFI interface: MobileSession, tools(), execute(), render_page ...
    rust/crates/*                        engine: parsing, rendering, editing, export, OCR, signing ...
```

* **Engine** - the PdfCraft Rust workspace in `rust/` (unchanged except for removing the desktop-UI-only dependencies
  from the workspace manifest). The library crate `pdfcraft-android` is a UniFFI `cdylib`; despite its name it builds
  for every OS (the logcat logger is compiled only on Android).
* **Bindings** - `scripts/gen_bindings.py` runs UniFFI's bindgen against the built library and writes
  `_bindings.py`, replacing only the library-loading function. Bindings embed per-function checksums, so a mismatching
  library is rejected at import time instead of crashing.
* **Tool table** - the engine ships 186 JSON-described tools (the same as PdfCraft's CLI/MCP). `data/tools_catalog.json`
  is a snapshot (regenerated by CI from the real library); at runtime the live table from the loaded library wins.
  `tools.py` turns each schema into a Python callable with a real signature and docstring; `scripts/gen_oneshot.py`
  writes `oneshot.py` (typed path-based functions).
* **Results** - `apply()` runs a tool on an opened copy and saves only if the document became dirty.
* **Wheels** - because the library is loaded with `ctypes`, nothing is compiled against a Python version, so wheels are
  `py3-none-<platform>`. `scripts/build_wheel.py` assembles them; CI builds the library for 12 targets.
* **Paths** - the engine requires absolute paths; pypdfcraft makes every path absolute and creates output folders.
